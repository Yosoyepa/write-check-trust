## Revisión 1 — Técnica (factibilidad contra el código real)

**P1 — Diagnóstico G-MUT-SITES legacy/ausente.** Factible y barato. Verificado en código: hoy manifiesto ausente y legacy schema 1 son **indistinguibles** (ambos dejan `previous = {}` en `tools/wct/mutate/engine.py:69-80`); el reporte no expone flag alguno y el gate (`runner.py:171-183`) emite solo `"{file}: excede max_sites_per_file con funciones cambiadas"` — exactamente el mensaje que en el piloto indujo a partir un archivo cuando el fix era regenerar el manifiesto. Diseño: `scan()` añade clave `"manifest": "ok"|"legacy"|"missing"` al reporte; el gate antepone una línea diagnóstica distinta por caso SOLO cuando ya hay findings (legacy sin archivos sobre el límite sigue pasando — no cambia la semántica de bloqueo). El formato del finding por archivo se conserva (los tests existentes asertyan por substring del path).

**P2 — Definition of done del coder.** Factible, texto puro. Verificado: `.claude/agents/coder.md` tiene 23 líneas (secciones Owns / Does not own / Handoff) y **cero** menciones de push, PR como cierre, handoff por sesión cortada, declaración de desviaciones o `fmt --staged` — las cuatro lecciones de las fases 22–24 no existen en el template. CORRECCIÓN a mi evaluación original: dije "sin rutas protegidas" y es falso — `.claude/agents/**` está protegido (policy.yaml:68, hash en integrity.lock:6) → requiere bless. Diseño: añadir sección `## Definition of done` (4 viñetas: push + PR abierta; si la sesión se corta, el handoff declara "queda sin commitear en la rama X"; el reporte declara TODA desviación del spec aunque sea benigna; al tocar archivos legacy, `wct fmt --staged`). ≤8 líneas nuevas, se respeta la tersidad del archivo.

**P3 — Matiz del runbook + skill wct-security.** La afirmación falsa ("el hook de pre-commit regenera el baseline") vive en un único lugar: `docs/runbook.md:9` (docs no protegido → libre). PERO la exploración reveló la causa real: `skills/wct-security/SKILL.md:8` instruye `detect-secrets scan --baseline .secrets.baseline`, y ese flag **reescribe** el archivo (ruta protegida) — cada agente que sigue el skill ensucia el lock y genera un bless innecesario. Corregir solo el runbook sería tratar el síntoma. Diseño: skill pasa a instruir escaneo sin reescritura (mismo patrón read-only que G-SECRET) + advertencia de que regenerar el baseline exige bless; se sincronizan las 3 copias byte-idénticas (`skills/`, `.claude/skills/`, `plugins/write-check-trust/skills/`). Runbook reescrito con honestidad: "el gate ya no lo ensucia; solo la regeneración manual (skill/regla propia del proyecto) toca el baseline, y eso requiere bless".

**P4 — `wct split-plan` (P8).** Factible con un límite de diseño honesto: `mutation_sites()` devuelve un entero por archivo — NO hay conteo por función, así que el plan necesita un helper nuevo `function_sites(path) -> dict[qualname, int]` (mismo conjunto de nodos que `mutation_sites`, atribuido a la función/método más interno; nodos a nivel de módulo → bucket `<module>`; la suma debe igualar el total del archivo). El agrupamiento es greedy en orden de fuente con tope `max_sites_per_file`; caso especial: una función que sola excede el límite → exit no-cero pidiendo partir LA FUNCIÓN, no el archivo. El nombre semántico de los submódulos no es automatizable: la propuesta nombra `<stem>_part{n}.py` y avisa "renombra semánticamente" (el piloto nombró auth_claims/auth_peer/auth_local con juicio humano). El comando SOLO propone (read-only): nunca mueve código — eso acota el riesgo de sobre-ingeniería.

```gherkin
# wct-split-plan-001
Feature: Split plan for mutation-heavy files

  El comando propone, nunca ejecuta: partición fachada de un archivo
  sobre el límite de sitios de mutación, según TEST-007.

  Scenario Outline: Proponer partición fachada bajo el presupuesto
    Given un archivo fuente con funciones de <sites> sitios y límite <limit>
    When pido el split-plan del archivo
    Then la propuesta tiene <parts> partes, cada una dentro del límite
    And el archivo original queda como fachada que re-exporta todo nombre público

      | 40,35,30       | 100   | 2     |
      | 50             | 100   | 1     |
      | 60,60,60,60    | 100   | 3     |

  Scenario: Una función que sola excede el límite no se arregla partiendo el archivo
    Given un archivo con una función de 140 sitios y límite 100
    When pido el split-plan del archivo
    Then el comando termina con exit no-cero pidiendo partir la función, no el archivo
```
