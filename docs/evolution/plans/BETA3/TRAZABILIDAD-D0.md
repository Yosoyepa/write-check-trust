## 2. Trazabilidad que debe acompañar cada PR del molde

Para cada campo activo congelar una fila con: ruta del dato y valor inicial /
perturbado → consumidor (archivo/función/argv o config materializada) → fixture
independiente → test recolectado → resultado observable → digest del artefacto
y run. Comparar significado, no solo texto generado. Cada campo sin consumidor
debe rechazarse o aparecer como no soportado; nunca quedar aceptado sin efecto.

Prueba de independencia del compilador: sustituir temporalmente en la fixture
su salida por un plan que omita un módulo o una prohibición y comprobar que el
expected externo conserva esa obligación y la calificación falla. No derivar
el expected desde el mismo plan bajo prueba. El fixture válido alternativo
protege frente a falsos positivos tanto como el negativo protege de escapes.

El reporte final diferencia `observed`, `required`, `excluded` y `unsupported`
por capacidad; no usa el número total de gates como denominador de confianza.
